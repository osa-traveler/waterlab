# 進め方のルール

このプロジェクトの目的は、**水面の波紋を、波動方程式の数値計算と3D描画で再現しながら、何が行われているかを理解すること**。
速く作ることよりも、1歩ごとに「何が変わったか」「どう確かめたか」を説明できることを優先する。
要件は [仕様書](spec/realtime_water_ripple_spec_v1.0_ja.md)、作業の履歴は [WORKLOG.md](WORKLOG.md) にある。

## ドキュメントの役割

| ファイル | 内容 | 更新するタイミング |
|---|---|---|
| `docs/spec/realtime_water_ripple_spec_v1.0_ja.md` | **要件**（v1.0の完成条件。式・単位・API・受け入れ基準） | 要件を変えるとき（理由を decisions に書く） |
| `docs/decisions.md` | 仕様書にない点・仕様書から変えた点と、その理由（D01, D02, …） | 判断したとき（必ず） |
| `docs/validation.md` | **Phaseごとの検証結果**（テスト、実測値、手動確認、未実行の項目） | 各Phaseの確認時 |
| `docs/WORKLOG.md` | **いつ・何をしたか**、到達点、次の一手 | 作業の終わり（毎回） |
| `docs/RENDERING_GUIDE.md` | **技術解説**（なぜそうするのか。式の意味、実測の数値、用語集） | 新しい概念を実装・説明したとき |
| `docs/WORKFLOW.md` | このファイル。進め方のルール | ルールを変えるとき |
| `docs/THIRD_PARTY.md` | 依存するサードパーティ（raylib）の入手方法・ライセンス・ハッシュ | 依存を足す・上げるとき |
| `docs/screenshots/` | 節目のスクリーンショット（WORKLOG から参照） | 節目ごと |

仕様書は「目標」、decisions は「判断の理由」、validation は「確かめた事実」、WORKLOG は「過去の記録」。混ぜない。

## 1回の作業の流れ

1. **現在地を確認する**: WORKLOG の最新の「到達点・次の一手」と、validation の未実行項目を読む。
2. **タスクを1つ選ぶ**: 仕様書のPhase順に進める。何が変わるはずか、どう確かめるかを先に決める。
3. **既存コードを確認する**: 推測で決めつけず、読んでから変更する。
4. **実装する**: 物理（core）は raylib に依存させない。挙動を比べたいものはスイッチで切り替えられるようにする。
5. **確認する**: ビルド、`ctest`、必要なら `--smoke-capture` の画像。数値は**測ったものだけ**を書く。
6. **説明する**: 「この処理で何が起きているか」を、コードを読まなくても分かる程度に説明する。長く残したい説明は RENDERING_GUIDE に足す。
7. **記録する**: WORKLOG に追記する。判断は decisions、検証結果は validation に書く。
8. **公開する**: コミットして GitHub に push する（下記の確認をしてから）。

## 記録のルール

- **未確認は未確認と書く**。測っていない数値、動かしていない機能を、完了・実測として書かない。
- **過去の記録に誤りが見つかったら、元の記録を消さず、訂正したことを明記する**。
- 性能値には、ビルド種別・格子・S・計測時間・機種を添える。
- **スクリーンショット**は `docs/screenshots/YYYY-MM-DD_内容-を-ハイフンで.png` に保存し、WORKLOG から参照する。アプリ自身の出力（`--smoke-capture`）を使う。画面全体のキャプチャは、無関係なウィンドウや個人情報が写り込むので使わない。

## 公開（GitHub）のルール

リポジトリ: <https://github.com/osa-traveler/waterlab>（公開）

- コミットの作者メールは、このリポジトリのローカル設定で GitHub の noreply アドレスにしている。個人のメールアドレスを使わない。
- push の前に、追加・変更したファイルに次のものがないか確認する: 個人のメールアドレス、ホームディレクトリなどの絶対パス、一時フォルダのパス、`.DS_Store`、エディタの個人設定。
- 他人の権利を侵害しない: 他人のコード・フォント・画像・モデルをリポジトリに入れない。依存はビルド時に取得し、[THIRD_PARTY.md](THIRD_PARTY.md) にライセンスと入手方法を書く。
- `build*/`、計測の CSV などの生成物はコミットしない（`.gitignore`）。
